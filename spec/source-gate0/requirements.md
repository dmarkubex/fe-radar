# 信源重建 Gate 0 — Requirements

状态：**APPROVED FOR EXECUTION**（用户于 2026-08-04 明确要求实施“信源重建 Gate 0”）。

## 1. 目标

Gate 0 是 FE-Radar 进入正式产业雷达验收前的阻断关卡。它验证的是“持续得到可信、相关、分散的产业信息”，不是数据库里配置了多少行信源。

## 2. 覆盖域

新闻信源必须覆盖以下六域，每域至少 2 个不同主办方的健康信源：

1. `own_company`：远东控股及成员企业动态、公告。
2. `products`：电线电缆、智能电网、新能源电缆、储能等公司产品相关动态。
3. `industry_policy`：电力、能源、储能、电缆、光通信的政策与行业动态。
4. `competitors`：主要竞品的公告、经营、项目与风险。
5. `upstream`：铜、铝、锂、化工材料等上游供给与价格驱动新闻。
6. `downstream`：电网、发电集团、EPC、房企/基建、储能集成商的招采与项目动态。

同一信源可以覆盖多个域，但同一域的 2 个名额必须来自不同主办方。quotes/datapro/websearch 属辅助信号，不计入新闻信源数量。

### 2.1 招标专项

大型企业公开招标是下游域的核心信号，不能只依赖媒体转述。Gate 0 还必须满足：

- 至少 2 个不同主办方的官方采购/招标平台通过单源准入，其中至少覆盖国家电网、南方电网之一。
- 招标源在配置中标记 `signalKinds: ["tender"]`，并按电线、电缆、导体、铜/铝、储能系统、电池、PCS、BMS、EMS 等项目关键词过滤。
- 只抓无需登录即可公开访问的公告列表和详情；不得绕过验证码、登录或 robots.txt。
- 标题、采购人、公告类型、原文 URL 和公告日期必须可追溯；中标公告与招标公告不得混为一类。

## 3. 单源准入

每个 Gate 0 新闻源必须同时满足：

- robots.txt 未明确禁止目标路径，代理不得绕过 robots。
- 在生产 worker 网络路径使用真实抓取器解析出至少 3 条。
- 抽样 20 条产业相关率不低于 80%；不足 20 条时检查全部，样本不得少于 3 条。
- 最新内容不超过该源配置的 `maxAgeHours`；未配置时按 168 小时。
- 标题、原文 URL、发布时间可追溯；不得用抓取时间冒充缺失的发布时间。
- 公网 LLM 不参与信源抓取、日期或数值提取。

## 4. 七日稳定性

Gate 0 最终通过必须满足连续 7 天生产观测：

- 每个计入覆盖的信源抓取成功率 ≥90%。
- 六个覆盖域每天均至少有 1 个健康信源，七日结束时每域仍有 ≥2 个健康信源。
- 招标专项每天至少有 1 个健康官方平台，七日结束时仍有 ≥2 个不同主办方的健康平台。
- 最近 7 天新闻产出中，单一信源占比 ≤30%，前三信源合计 ≤60%。
- 生产队列无持续积压，抓取失败不会导致整个代理池或后续信源复检失真。

## 5. 状态与发布语义

- `PASS`：单源准入和七日稳定性全部满足。
- `BLOCKED`：七日窗口尚未完成或覆盖域不足；不是通过。
- `FAIL`：任一硬阈值不满足。
- Gate 0 未 PASS 前，产品必须标记为试运行，不得按正式产业雷达验收。

## 6. 合规与安全

- 索比、雪球、搜狗微信等已登记 robots 禁止源保持禁用且不得复检绕过。
- 不保存原始 HTML；仅保存标准化条目和抓取运行元数据。
- 信源、覆盖域和 cadence 配置存数据库，不硬编码到业务逻辑。
- Firecrawl-C1 在裸“远东”误配修复前保持禁用。
