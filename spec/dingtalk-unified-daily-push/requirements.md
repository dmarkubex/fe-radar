# 钉钉合并日报推送需求

状态：Ready for Grok Implementation

日期：2026-08-06

## 生产事实

- `daily_reports` 已连续生成，但没有产业日报钉钉推送任务。
- `briefing_targets` 与 `commodity_briefings` 当前均为空，现有简报推送无法发送。
- 简报推送时间 `16:05` 写死在 worker 常量中，后台只能维护目标，不能启停或修改发送时间。
- 现有测试发送只发纯文本，不含日报/简报深链，不能验收钉钉内免登。

## 目标

每天按管理员配置的时间，向所有启用的 `briefing_targets` 发送一张合并 ActionCard。卡片优先展示产业日报摘要；有铜锂简报时同时展示行情状态并提供第二个详情按钮。任一内容缺失时仍可用另一份内容发送，避免空消息。

## 功能需求

- FR-01：复用 `briefing_targets`，不新增第二套 webhook/secret 模型。
- FR-02：新增数据库单例配置，至少包含启停、发送时间、发送日模式（每日/工作日）、站内访问基址；时区固定 `Asia/Shanghai`。
- FR-03：后台 `/admin/briefing/targets` 同页展示并维护调度配置，保存后下一分钟生效，无需重启 worker。
- FR-04：调度 worker 每分钟读取数据库配置，仅在配置时间命中时执行；同一日期、同一目标最多成功发送一次。
- FR-05：合并卡片读取当天 `daily_reports` 与状态为 `succeeded/degraded` 的 `commodity_briefings`。两者都不存在时不发送并写结构化日志。
- FR-06：有产业日报时提供 `/daily?date=YYYY-MM-DD` 按钮；有铜锂简报时提供 `/briefing/{id}` 按钮。URL 必须由数据库配置的站内基址生成。
- FR-07：产业日报存在、简报不存在时仍发送；简报存在、产业日报不存在时仍发送；两者都存在时发送一张合并卡片，不发两张重复卡片。
- FR-08：每个目标写独立推送审计，包含日期、目标、可选简报 ID、内容存在标记、状态、尝试次数、错误和成功时间。
- FR-09：失败沿用三次指数退避；单个目标失败不阻塞其他目标。
- FR-10：现有“测试推送”改为真实合并 ActionCard，使用当天实际数据和同样的深链构造规则；不写正式推送成功审计。
- FR-11：简报生成成功后不再立即发送单独卡片；现有手工“重推简报”能力保留，避免破坏 v1.1 运维入口。

## 非功能需求

- NFR-01：配置必须存数据库；不得把业务发送时间继续硬编码成最终决策。
- NFR-02：Webhook URL 与 sign secret 不得进入日志、API 明文响应或测试输出。
- NFR-03：数据库迁移使用 `0055`，不得改已存在或当前未提交的 `0054_websearch_quality_config.sql`。
- NFR-04：不修改现有用户认证、Cookie、钉钉免登和 RBAC 语义。
- NFR-05：不新增依赖；复用 `sendActionCard()`、现有目标 API/UI 与 BullMQ 队列。
- NFR-06：`baseUrl` 只接受 `http:`/`https:` 绝对 URL，保存时去除末尾 `/`；卡片路径固定由代码拼接，不能由用户输入任意按钮 URL。
- NFR-07：配置默认 `enabled=false`，迁移/部署本身不得向任何群自动发消息。

## 验收

- 管理员可在后台看到并保存启停、`HH:mm`、每日/工作日和站内基址。
- 保存后无需重启；命中分钟时仅发送一次，重复 tick 不重复发送。
- 只有日报、只有简报、两者都有、两者都无四种情况均有自动化测试。
- 测试发送收到真实 ActionCard；卡片按钮为当前 FE-Radar 内网地址，并可进入已部署的钉钉免登流程。
- 目标为空时明确显示并跳过，不将“调度已启用”误报成“推送成功”。
