# A-6（High，复合）— playwright 源可永久静默断供，两道闸门同时绿

## 已观测事实（第二轮 qoder 发现，第三轮复核仍 NOT-FIXED）

三处代码构成一条完整的静默失效链：

1. `apps/worker/src/fetchers/playwright.ts:214-232` —— `extractItems` 零匹配时**直接返回 `[]`**，
   不抛错。对照 `apps/worker/src/fetchers/html.ts:129-134`，html 路径有
   `if (filtered.length === 0) throw new SourceFetchError("FETCH_HTML_EMPTY", ...)`。
   **两条路径不对称，playwright 少了这层保护。**
2. `apps/worker/src/handlers/fetch.ts:191-193` —— `if (accepted.length === 0) { markSourceSuccess(); return; }`
   零条目被记为**成功**。
3. `packages/db/scripts/verify-sources.ts:173-181` —— CI 门禁用 **`waitFor`** 选择器计数，
   而不是运行时真正决定抽取结果的 **`itemSelector`**。

**失败场景**：站点改版导致 `itemSelector` 失配，但 `waitFor`（常是 `body` 或
`.news-list` 这类粗选择器）仍能命中 →

- CI 门禁 `$$eval(waitFor)` 计数 > 0 → **绿**
- 运行时抽取 0 条 → `markSourceSuccess` → 健康记录 **绿**
- 实际该源每周期零入库，无告警、无 fail_count 增长

**两道本该互相兜底的闸门，因为看的是不同的东西，同时失效。**

## 要做的事

1. `playwright.ts`：`extractItems` 零匹配时抛 `SourceFetchError`
   （错误码与 html 路径对齐，如 `FETCH_PLAYWRIGHT_EMPTY`），与 `html.ts:129` 同语义。
2. `verify-sources.ts`：计数改用 `itemSelector`（第 117-125 行附近已经读出该字段，只差用上），
   错误信息也应指明是 itemSelector 失配。
   `waitFor` 继续用于等待页面就绪——**两者职责不同，不要混用**。

# rss 单条坏 item 作废整 feed（Medium）

`apps/worker/src/fetchers/rss.ts:29-31` —— 单条 item 缺 title 或 link 即 `throw FETCH_RSS_INVALID`，
整个 feed 本周期零入库。

**与项目自身规范矛盾**：`apps/worker/src/fetchers/announcements/__tests__/sse.test.ts:194`
有一条用例明确钉住"skips malformed records while keeping valid ones"——
sse 路径是跳过坏记录保留好的，rss 路径却是全盘作废。

**失败场景**：feed 30 条里有 1 条缺 `<link>` → 整源本周期 0 入库；
只要该条目还在 feed 里，每周期重复失败。

修法：坏 item 跳过并 warn（记录被跳过的条数），**全部无效时才抛错**。
