## 已观测缺陷

`packages/db/migrations/0061_legacy_viewer_credential_purge.sql:29` 与 `:38`
两个分支都限定了 `role = 'viewer'`：

```sql
WHERE username = 'viewer' AND role = 'viewer' AND dingtalk_id IS NOT NULL ...
WHERE username = 'viewer' AND role = 'viewer' AND dingtalk_id IS NULL ...
```

**失败场景**：仓库公开默认账号 `viewer` / `viewer-password` 建立后，
被管理员**提权为 editor 或 admin**（角色变了，username 没变），并绑定钉钉。
0061 因 `role='viewer'` 匹配不到该行 → `password_hash` 保留 →
运维开启 `EMERGENCY_LOCAL_LOGIN=true` 后，**攻击者用仓库里公开的默认口令登录高权限账号**。

角色越高，危害越大——而迁移偏偏只覆盖角色最低的情形。

## 附带问题（一并修）

`packages/db/src/__tests__/migration-0061-legacy-viewer.test.ts:34`
**把错误的角色条件固化进了断言**，且该测试**只检查 SQL 字符串、从不执行迁移**——
所以它对这个缺陷零拦截能力。

## 要做的事

1. 两个分支去掉 `role = 'viewer'` 条件，改以 **username + 钉钉绑定状态 + 凭据状态** 分流：
   - 有 `dingtalk_id` 且 `password_hash IS NOT NULL` → 清 `password_hash` + bump `token_version`（**不禁用账号**，它是正常的钉钉账号）
   - 无 `dingtalk_id` 且 `disabled_at IS NULL` → 禁用 + bump（原逻辑）
     幂等守卫保留（重跑零行）。
2. 修测试：让它**真正执行迁移**而不是比对 SQL 字符串。
   若本仓库测试环境无法起真实 Postgres，**停下并在 handoff.md 说明**，
