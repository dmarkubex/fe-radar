## 背景：为什么不再补检测器

编辑员可在后台配置正则，worker 用它从行情文本抽数值。当前用 `new RegExp` 同步执行，
可被灾难性回溯打死。已连续三轮扩静态检测器、三轮被绕过：

| 轮次 | 补了什么                              | 随后被什么绕过     |
| ---- | ------------------------------------- | ------------------ | --------- |
| R1   | `\([^()]*[+*][^()]*\)\s*[+*]`         | `(a+){2,}`         |
| R2   | 上式加 `\{` 分支 + 相邻同基 tokenizer | `^a+a+a+a+…$`      |
| R3   | 重叠交替检测                          | `((a+)){2,}$`、`(a | aa){2,}$` |

**主会话实测（当前代码）**：

```
((a+)){2,}$   schema 放行   n=34 输入回溯 65906.3 ms   ← 66 秒
(a|aa){2,}$   schema 放行   n=30 输入回溯   173.0 ms
```

一条保存的规则即可锁死 worker 单事件循环 66 秒（运行时允许 2000 字符输入）。

**用户已决定改用原生 `re2`**。RE2 是线性时间引擎，**不做回溯**，
灾难性回溯在其架构上不存在——这是结构性消除，不是再加一层检测。

## 兼容性（主会话已核实，可直接依赖）

`packages/db/migrations/0009_commodity_seed.sql` 中全部现存 `regex_rules` 的 pattern
**只使用 `(?:...)` 非捕获组、字符类、量词，零处前后瞻 `(?=`/`(?!`/`(?<`、零处反向引用**
→ RE2 全部支持，不会打破既有配置。

典型形态：`(?:现货|均价|报价)[^\d]*(\d+(?:\.\d+)?)`

## 要做的事

### 1. worker 侧改用 RE2（**这是安全修复的本体，必做**）

`apps/worker/src/fetchers/quotes/rsshub-extract.ts:195`：

```ts
const re = new RegExp(rule.pattern, "i"); // 改为 RE2
const match = re.exec(text);
```

RE2 的 `exec()` / 分组下标语义与 `RegExp` 一致，`match[groupIndex]` 用法不变。

**必须处理 RE2 构造失败**：RE2 不支持的语法（前后瞻、反向引用）会在构造时抛错。
捕获它 → **跳过该规则并 warn（含 pattern 与 metric_key）** → 继续处理其余规则。
**不要让一条不兼容的规则打挂整个 quotes-fetch job。**

### 2. web 侧保存时校验（决定编辑员能否得到反馈）

`apps/web/lib/api/sources-schema.ts` 当前用 `isSafeRegex()` —— 内含
三个检测器常量 + `hasAdjacentSameBaseQuantifiers` tokenizer，约 100 行。

**若 web 侧也能引入 re2**：把 `isSafeRegex` 改为「用 RE2 编译一次，编译通过即安全」，
并**删除那三个检测器常量与整个 tokenizer**。
理由：RE2 可编译 ⇒ 线性时间 ⇒ 安全，静态启发式不再有存在意义，
而它已经连续三轮产生 High，留着只会制造虚假信心。

**若 web 侧引入 re2 有阻碍**（例如 `deploy/Dockerfile.web` 加编译链导致构建失败）：
**停下，把阻碍写进 handoff.md**，保持 web 侧现状不动，只完成第 1 步。
安全属性由 worker 侧保证，web 侧只是保存时的 UX 反馈。**不要为了统一而强行改。**

### 3. Dockerfile 编译链

`re2` 是原生模块，需要 node-gyp 工具链。当前两个 Dockerfile 的 builder 阶段
**都没有** python3 / make / g++（只在 runner 阶段装了 ca-certificates、postgresql-client）。

- `deploy/Dockerfile.worker`：deps/builder 阶段加编译链
- `deploy/Dockerfile.web`：仅当第 2 步选择引入 re2 时才需要改

注意这是**多阶段构建**：编译链只需在 deps/builder 阶段，**不要装进 runner 阶段**
（会让运行镜像无谓变大）。原生 .node 产物需正确复制到 runner。

## 必须新增的测试

1. **回代验算向量**——下列 pattern 在**新逻辑**下必须不再能锁死执行：
   ```
   ((a+)){2,}$      (a|aa){2,}$      (a+){2,}      ^a+a+a+a+a+a+a+a+a+a+$
   (x+x+)+y         [0-9]+[0-9]+[0-9]+x
   ```
   断言方式：对 `"a".repeat(40)+"!"` 执行，**实测耗时应在毫秒级**（给个宽松上限如 100ms）。
   注意：RE2 下这些 pattern 可能**编译成功且执行飞快**（因为不回溯）——
   那就是正确结果，不必再拒绝它们。
2. **兼容性回归**：`0009_commodity_seed.sql` 里 7 条真实 pattern 逐条代入，
   对典型行情文本仍能抽出正确数值（不只是"能编译"）。
3. RE2 不支持的语法（如 `(?=x)`）→ 该规则被跳过并 warn，**其余规则仍正常处理**。
