# A-10（Medium）— 限速测试重新实现了一遍算法，没执行生产 Lua

`packages/core/src/__tests__/quota.test.ts:127`、
`apps/web/lib/auth/__tests__/login-rate-limit.test.ts:13`

两处的 fake Redis **在 JS 里重写了一遍正确的限速语义**，而不是执行
`packages/core/src/quota.ts:122` 导出的 `LOGIN_ADMIT_LUA` 脚本本身。

**失败场景（codex 实测）**：把生产 Lua 里的 `if u >= limit or i >= limit` 改成 `and`，
两个 fake 仍按自己实现的 `or` 语义工作，**测试继续全绿**；
而真实 Redis 中"任一独立计数器达上限即拒"的语义已被破坏——
单个计数器超限时仍会放行。

这直接威胁项目硬约束「双独立计数器」。

## 要做的事

**首选**：用一个能真正执行 Lua 的方式验证导出的脚本常量
（临时 Redis 容器、或 `ioredis-mock` 之类支持 `eval` 的库——**先确认该库是否真执行 Lua**，
很多 mock 库的 `eval` 是空壳）。至少覆盖：

- 两键独立阈值（任一达上限即拒）
- 并发预占（N 个并发只放行 limit 次）
- TTL 首次设置

**若本仓库环境确实无法执行 Lua**：
停下，把限制写进 handoff.md，并把 mock 测试的**断言范围收窄**为"wrapper 传参正确"
（keys 数量、ARGV 顺序、键名格式），**同时在测试文件顶部注释写明
「本测试不验证 Lua 语义，Lua 正确性未被任何测试覆盖」**。
把已知缺口显式化，比留一个看起来在测语义的假测试好。

# A-12（Medium）— 四个 handler 测试把 withScrubber mock 成 identity

`apps/worker/src/handlers/__tests__/{embedder,ner,prefilter,scorer}.test.ts`

四处都是 `vi.fn((client) => client)`，只断言"以 `{projectCodes:[...]}` 调用了 mock"。
**scrubber 实际不做任何替换，测试照样全绿。**

**失败场景**：有人误改 `withScrubber(client, ctx)` 漏传 ctx、
或 PROJECT_CODE 替换分支回归 → **项目代号裸奔进公网 LLM，CI 全绿无感知**。
这直接威胁项目硬约束「公网 LLM 调用前必经 scrubber」。

## 要做的事

至少一个 handler 改为**不 mock `withScrubber`**，用假 `LlmClient` 捕获最终发出的
`request.user`，断言其中**真实代号已被 `[REDACTED:PROJECT_CODE:` 替换**。

断言方式要求：**断言原始代号子串不出现在最终 payload 里**，
而不是断言"某函数被调用过"——前者能覆盖你没想到的字段，后者不能。

# 附带（Medium）— embedder 注入代号字典造成向量漂移

`apps/worker/src/handlers/embedder.ts:27-29` 给**本地 Qwen** 也传了 `projectCodes`。

Qwen 不出公网，遮蔽零安全收益，但 embedding 是对
`[REDACTED:PROJECT_CODE:hash8]` 文本计算的，而 DB 存的是原文：

- 含代号 item 的向量缺失代号语义 → 聚簇相似度系统性偏移
- admin 日后新增代号 → 新旧 item 按不同字典取向量，**embedding 只算一次不重算，漂移永久存在**

附带：内容含内网 IP 时 `withScrubber.embedding` 抛 `SCRUBBER_BLOCKED`，
embedder 无 catch → BullMQ 对永不成功的 job 反复重试。

修法：embedder 的 `withScrubber` **不传 projectCodes**（本地模型可整体豁免代号遮蔽），
并对 `SCRUBBER_BLOCKED` catch-and-skip。

**先确认 Qwen 确实是本地不出网的**（读 `packages/llm` 的 provider 配置），
把依据写进 handoff.md——如果它其实走公网网关，这条修法就是错的，那时停下报告。
