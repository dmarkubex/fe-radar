## 背景：S8 只修好了一半，且原因在任务单而非实现

S8 已把检测器扩成 `/\([^()]*[+*][^()]*\)\s*(?:[+*]|\{)/`，成功堵住
`(a+){2,}` / `(a+){25}` / `(x+x+)+y`。**这部分是对的，不要回退。**

但**无括号的相邻无界量词家族仍可绕过**，主会话实测（直接跑两个检测器常量）：

```
(a+){2,}                 命中 ✓
(a+){25}                 命中 ✓
(x+x+)+y                 命中 ✓
^a+a+a+a+a+a+a+a+a+a+$   命中 = false   ← 漏
```

原因：`ADJACENT_DOUBLE_QUANTIFIER = /[+*]\s*[+*](?!\+)/` 找的是**紧邻**的两个量词，
而 `a+a+` 的两个 `+` 被 `a` 隔开；`NESTED_UNBOUNDED_QUANTIFIER` 要求有括号分组。两者都不命中。

**它是真的灾难性回溯**，主会话实测 `/^a+a+a+a+a+a+a+a+a+a+$/` 对 `"a".repeat(n)+"!"`：

```
n=22 →   8.8 ms
n=26 →  20.3 ms
n=30 → 101.3 ms      每多 2 个字符约翻倍
```

运行时允许输入 2000 字符 → worker 单事件循环被无限期占死。

### 必须放行（过度拦截同样是缺陷）

以下是真实业务正则，来自 `packages/db/migrations/0009_commodity_seed.sql` 等 seed，
**误拦会让既有 quotes 信源保存不了**：

```
([0-9.]+)\s*元/吨
价格[:：]\s*([\d,]+)
LME铜\s*([0-9]+\.?[0-9]*)
收盘价\s*(\d{4,6})
```

**注意 `LME铜\s*([0-9]+\.?[0-9]*)` 含 3 个无界量词**（`*`、`+`、`*`）——
所以"无界量词总数 ≥3 即拒"这类朴素计数法会误伤，不要用。
