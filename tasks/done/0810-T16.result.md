### 缺陷

池满后 `BrowserContextPool.acquire()` 纯 round-robin，不看 `slot.proxy?.disabled`。T15a 修正打分对象后，坏代理能被正确标 `disabled`，但 playwright 仍会一直复用绑定该代理的 slot。

### 修法（`playwright.ts`）

池满时：

1. 从 RR 起点遍历，跳过 `proxy?.disabled === true`，优先返回健康 slot（仍返回 **slot 绑定身份**，T15a 语义不变）。
2. 全部禁用 → 就地重建 RR slot：关旧 context → 同 browser `newContext(请求 UA/proxy)` → **重装** `installSubresourceGuard` → 更新 `context/userAgent/proxy`。

### 测试

新增 `T16: skips disabled-proxy slots on pool reuse; rebuilds when all slots disabled`：

- 单 slot 禁用 → 返回另一健康 slot（非 disabled、非静默丢弃的新 proxy）
- 全禁用 → 重建为请求 proxy，且 `context.route` 再装一次
