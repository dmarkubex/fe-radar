# 缺陷 A（High）— ReDoS 静态检测可被有界重复量词绕过

## 已观测事实（主会话已验证）

`apps/web/lib/api/sources-schema.ts:43` 的检测器：

```js
NESTED_UNBOUNDED_QUANTIFIER = /\([^()]*[+*][^()]*\)\s*[+*]/;
ADJACENT_DOUBLE_QUANTIFIER = /[+*]\s*[+*](?!\+)/;
```

第一条要求 `)` 后紧跟 `+` 或 `*`。**`(a+){2,}` 的 `)` 后面是 `{`，不命中**；
第二条也不命中。故 `(a+){2,}` / `(a+){25}` 这类"组内无界量词 + 组外有界重复"可通过保存校验。

运行时 `apps/worker/src/fetchers/quotes/rsshub-extract.ts:62` 附近对截断后仍达 2000 字符的
输入同步 `exec`，**无超时、也不复跑 `isSafeRegex`**。

**失败场景**：编辑员保存 `regex_rules:[{pattern:"(a+){2,}", metric_key:"x"}]`（zod 放行）
→ 15:30 quotes-fetch 命中一段上百个 `a` 后接非匹配尾的 feed 文本 → 指数回溯
→ **worker 单事件循环卡死**，同进程全部 BullMQ job（pipeline / scheduler / briefing）停摆到重启。

## 要做的事

1. 检测器扩为"组后跟 `[+*]` **或 `{`**"即拒，例如
   `/\([^()]*[+*][^()]*\)\s*(?:[+*]|\{)/`。
2. **worker 运行时在 `applyRegexRules` 执行前复跑同一 `isSafeRegex`**，不合格的规则跳过并 warn。
   这一步不可省——它堵住"seed / 直写 DB 绕过 API 校验"的路径。
3. 建议同时把 exec 输入再截短（≤100KB 之类），作为纵深防御。

## ⚠ 明确不要做

**不要加"执行探针"**（编译后拿对抗性输入 `test()` 一下看耗时）。
`sources-schema.ts` 的注释已写明理由：Node 同步正则不可中断，
探针本身会挂死 Next.js 事件循环，比它要防的 worker ReDoS 更严重。**尊重这个约束。**

# 缺陷 B（High）— `selectors.date` 三方不一致，锁死 8 个生产信源

## 已观测事实

- `apps/web/lib/api/sources-schema.ts:207`：`date` 为 `z.string().min(1)`（要求非空）
- `apps/worker/src/fetchers/html.ts:104-112`：**明确支持 `date:""`**，回退用抓取时间
- 生产 seed：`migrations/0022`（bjx 6 源）与 `0023`（escn / tmtpost）**全是 `"date":""`**

**失败场景**：admin 对这 8 个源中任意一个做**任何**保存（改 keywordFilter、换 listUrl、
甚至只改 tier 而表单原样回传 config）→ `PUT /api/sources/[id]` 经 `updateSourceSchema`
→ 400 VALIDATION。"能跑但改不了"。
且 `sources-schema.test.ts` 所有 html 用例都用了非空 date，测试恒绿掩盖了矛盾。

## 要做的事

`date` 改为 `z.string()`（允许空串，与 worker 语义对齐），字段保持必填。
补一条**用 0022 真实 seed 配置原样过校验**的回归测试。
