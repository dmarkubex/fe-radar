## 背景

本项目已实现 `requireFreshRole()`（`apps/web/lib/auth/token-freshness.ts`），
用于在**每次请求时查库**核对 `users.disabled_at` 与 `users.token_version`，
使"停用账号 / 降权 / 改密码"能立即让既有 JWT 失效，而不必等 token 自然过期（最长 2h）。

**它目前只接了 22 个特权 API route，两大类入口完全没接。**

## 已观测缺陷（必须回代验算）

### 缺陷 A — 整个 admin 页面面零覆盖（High）

实测命令与结果：

```
$ grep -rln "requireFreshRole" "apps/web/app/(admin)/"
(无输出 —— 零命中)
```

不是某个页面遗漏，是**所有 admin Server Component 页面都没有**。
它们仅依赖 `apps/web/middleware.ts` 中**只解析 JWT 内旧角色**的判断（Edge runtime 不查库）。

`apps/web/app/(admin)/admin/users/page.tsx` 随后直接 `getDb().select(...)`，
返回 `username / dingtalkId / name / dept / role / disabledAt` 全量用户表 + 待处理合并冲突。

**失败场景**：10:00 admin A 被停用（`disabled_at` 置位、`token_version` 递增）→
A 用停用前的 cookie 打开 `/admin/users` → 页面正常渲染，读到全部用户的 unionid 与部门。
最长可持续到 token 自然过期（2h）。

### 缺陷 B — 只读 API 不查库（High）

实测：以下 route 均无 `requireFreshRole`（`apps/web/app/api/auth/[...nextauth]/route.ts`
是认证端点本身，**不在范围内、不要动**）：

```
apps/web/app/api/daily/route.ts
apps/web/app/api/search/route.ts
apps/web/app/api/alerts/route.ts
apps/web/app/api/alerts/count/route.ts
apps/web/app/api/briefing/route.ts
apps/web/app/api/briefing/[id]/route.ts
apps/web/app/api/briefing/[id]/download/route.ts
apps/web/app/api/timeline/route.ts
apps/web/app/api/quotes/latest/route.ts
apps/web/app/api/items/[id]/route.ts
apps/web/app/api/items/[id]/feedback/route.ts
```

**失败场景**：被停用的 viewer 用旧 cookie 继续调 `/api/timeline`、`/api/search`
读取全部内部情报；调 `/api/briefing/[id]/download` 下载采购敏感的铜锂简报 docx；
`POST /api/items/[id]/feedback` 是**写**接口，同样不查库。

## 要做的事

### A — 新建 admin 统一 gate

`apps/web/app/(admin)/` 目前**没有 layout.tsx**。新建一个：

- `apps/web/app/(admin)/layout.tsx`，在渲染 children 前执行 admin 级新鲜度校验，
  不通过则重定向到登录页（或渲染 403）。
- 必须是 **Node runtime**（要查库），不要放进 Edge。
- 校验后所有 `(admin)/**` 页面自动被覆盖，**不要**逐个页面去改。

### B — 只读接口接入

给上方 11 个 route 加 viewer 级新鲜度校验。
`feedback` 是写接口，与其余只读接口同等对待即可（都要查库）。

## 必须新增的测试

1. 停用账号（`disabled_at` 非空）持旧 JWT 调 `/api/timeline` → 401/403，不返回数据。
2. `token_version` 已递增、JWT 内为旧版本 → 同样被拒。
3. 正常在职账号 → 正常返回（防止过度拦截）。
4. `feedback` POST 在账号停用后被拒。
5. admin layout：停用的 admin 被重定向/403；在职 admin 正常渲染。
