# T9 — 阻断提交的两个 lint 错误（含一处真实正则语义 bug）

- executor: `grok`

## ⚠ 本任务禁止 git 提交

不要 `git commit` / `add` / `stash` / `reset` / `checkout <文件>`。改动留工作区。
进度**追加**到 `handoff.md` 末尾。跑命令用 `2>&1`。

## 背景

`git commit` 的 pre-commit 钩子（`lint-staged`）拦住了本轮全部改动，报两个错误：

```
apps/worker/src/fetchers/quotes/__tests__/rsshub-extract.test.ts
  16:46  error  `import()` type annotations are forbidden  @typescript-eslint/consistent-type-imports

apps/worker/src/lib/__tests__/robots.test.ts
  96:90  error  Unnecessary escape character: \z  no-useless-escape
```

## 缺陷 1（风格）— `rsshub-extract.test.ts:16`

```ts
const actual = await importOriginal<typeof import("@fe-radar/shared")>();
```

内联 `import()` 类型标注被项目 eslint 规则禁止（要求走顶层 `import type`）。
修法：在文件顶部加 `import type * as Shared from "@fe-radar/shared";`，
然后改为 `importOriginal<typeof Shared>()`。

## 缺陷 2（真实 bug，不只是风格）— `robots.test.ts:96`

```ts
const workerBlock = content.match(
  /^[ \t]{2}worker:\n([\s\S]*?)(?=^[ \t]{2}[a-zA-Z_]|\z)/m
);
```

`\z` 在 JavaScript 正则里**不是合法转义**（这是 Python/Ruby/Perl 的"字符串结尾"语法，
JS 没有）。ESLint 把它当"无意义转义"报出来是对的，但后果比"风格问题"更严重：
**该转义被静默忽略后，`\z` 在正则里退化成字面字符 `z`**，意味着这条 lookahead
实际匹配的是"下一行是 2 空格+字母开头，或者遇到字面字符 z"——完全偏离了
"匹配到 YAML 该 service 块结尾或整个文件结尾"的原意。

**必须用 JS 里正确的"字符串真正结尾"写法替换 `\z`**：`(?!.|\n)`
（负向先行断言"后面不再有任何字符"，等价于字符串结尾，且不受 `/m`、`/s` flag 影响）。

修法：

```ts
const workerBlock = content.match(
  /^[ \t]{2}worker:\n([\s\S]*?)(?=^[ \t]{2}[a-zA-Z_]|(?!.|\n))/m
);
```

**修完后必须验证该测试原本要断言的行为没有跑偏**——用一个真实的
`deploy/stack.yml` 片段（worker 块后面还有其它 service，以及 worker 块是文件最后一个
service 两种情况）手工验证正则确实能正确截出 worker 块。
