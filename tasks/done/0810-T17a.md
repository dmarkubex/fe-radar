## 队列载荷判别联合（`queues.ts`）

当前 `BriefingPushJob`（:129-131）只有 `{ briefingId: number }`，`briefingId===0`
表示分钟 tick、正数表示手工 briefing 重推，两种含义挤在一个字段里。
按规格"施工清单"的要求：

- 改成最小判别联合，至少覆盖三种：分钟 tick（sentinel）、briefing 手工重推
  （携带 `briefingId` + `trigger: "manual"`）、产业日报手工重推
  （携带 `reportDate` + `trigger: "manual"`，不依赖 `briefingId`）。
- 具体类型命名和字段自定，但**判别字段必须能让 `bootstrap.ts` 的 worker
  handler 无歧义地分出这三种**，不能继续靠"`briefingId` 是不是 0"这种隐式判断
  （规格明确要求"不依赖共同 `jobId` 实现业务幂等"，判别应该是显式字段）。
- `createBriefingPushQueue`/`QUEUE_BRIEFING_PUSH` 队列本身不用拆（继续共用
  同一个 BullMQ 队列，只是 payload 类型精确化）。
- 改完这个类型后，`bootstrap.ts` 里 `briefingPushWorker` 的 handler
  （:252-280）要跟着适配新判别类型——\*\*但 briefing 手工重推分支
  （`runBriefingPush(job.data.briefingId)`）本次只做"payload 加 trigger 标记
  - handler 能正确路由到它"，不要改 `runBriefingPush` 函数本身的内部逻辑\*\*
    （那是 T17b 的范围）。
- 新增一个 handler 分支处理"产业日报手工重推"类型的 job：调用
  `daily-push.ts` 里你新增的人工 reclaim 函数（函数名自定，作为
  `runScheduledDailyPush` 之外的新导出函数，例如 `runManualDailyPush(reportDate)`），
  日期来自 job payload。
