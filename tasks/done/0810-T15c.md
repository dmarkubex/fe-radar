# 背景（第八轮全量 diff 复审，裁判已独立核实为真）

## 缺陷 1（Medium）— packages/db 未声明 playwright 依赖，CI 门禁静默失效

`packages/db/package.json` 的 `dependencies`/`devDependencies` 都没有 `playwright`
（只有 `apps/worker/package.json` 声明了 `"playwright": "^1.59.1"`，作为 `dependencies`）。
`packages/db/scripts/verify-sources.ts:162-163`：

```ts
// @ts-expect-error -- playwright is a workspace-level dep (apps/worker), not declared in @fe-radar/db
const pw = await import("playwright");
```

写这段代码的人已经知道这个缺口，用类型抑制注释放行、靠 `catch` 兜底"playwright package
not available"不崩溃。但在 pnpm 严格 workspace 隔离下（本项目默认行为，`packages/db`
不会因为 `apps/worker` 声明了某个依赖就能 import 到它），`import("playwright")`
**运行时会真的解析失败**，被 :232 附近的 `catch` 捕获成"不可用"，**这个包本该验证的
playwright 类信源 CI 校验会静默跳过，不是真的跑了检查**。

**修法**：`packages/db/package.json` 的 `devDependencies` 里加
`"playwright": "^1.59.1"`（跟 `apps/worker/package.json` 保持同一版本号，
这是个纯校验脚本用的工具依赖，不是运行时 API，放 devDependencies 不放 dependencies）。
加完后跑 `pnpm install`（workspace 根目录跑，不要单独在 packages/db 目录跑）建立
lockfile 关联；去掉 `verify-sources.ts:162` 的 `@ts-expect-error` 注释（依赖声明后
类型检查应该能过，若还有类型错误如实报告，不要为了消掉报错乱加 `as any`）。

## 缺陷 2（Medium，与 T15a 缺陷 2 同类，跨文件镜像未同步）

`checkPlaywright`（函数体约 :143 起）目前**完全没有捕获导航后的真实落点**
（不像 `apps/worker/src/fetchers/playwright.ts` 那样有 `const finalUrl = page.url();`）。
`page.goto(targetUrl, ...)`（:166）之后直接 `waitForSelector`，然后 `$$eval` 里
把 `listUrl: targetUrl`（:212 附近，`{ titleSelector, linkSelector, listUrl: targetUrl, limit }`）
原样传给浏览器侧函数，浏览器侧函数（:191-210）用这个 `listUrl` 做"href 是否回退成
列表页本身"的判定基准——**这跟 T15a 修复前的 `playwright.ts` 是同一个 bug**：
若目标站点有重定向，浏览器把空 href 解析成重定向后的真实文档地址，但这里拿重定向前的
`targetUrl` 去比较，判定永远不触发，垃圾条目被当有效条目放行。

这个问题本质上是"两个文件里维护了同一份判定逻辑的两份拷贝，一份修了另一份没跟着修"——
T13 当时特意把这两处判定逻辑对齐过（第六轮 V-2 就是因为这两处不一致被打回过一次），
所以这次也必须同步修，不能只修 `playwright.ts` 那一份。

**修法**：`page.goto(...)` 之后（:169 后）加一行 `const finalUrl = page.url();`
（这个方法在 `verify-sources.ts` 顶部约 :145 的 `browser` 类型声明里已经有
`newPage: () => Promise<{ ... }>` 这个内联类型，需要给这个内联页面类型加一个
`url: () => string` 方法签名，跟 `apps/worker/src/fetchers/playwright.ts` 的
`PageLike.url()` 保持同名同语义）。把 `$$eval` 调用里的 `listUrl: targetUrl`
改成 `listUrl: finalUrl`。
