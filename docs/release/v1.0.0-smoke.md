# FE-Radar v1.0.0 Release Smoke

## Local gates

- PASS `pnpm -r typecheck`
- PASS `pnpm -r lint`
- PASS `pnpm -r test`
- PASS `pnpm -r build`
- PASS `pnpm madge --circular apps packages`
- LOCAL PREREQ `pnpm --filter @fe-radar/web e2e --grep "release smoke" --grep-invert "@v11"`
  - Requires a migrated local Postgres at `postgres://fe_radar:fe_radar_dev@localhost:5432/fe_radar`.
  - Seed admin with `SEED_ADMIN_USERNAME=admin SEED_ADMIN_PASSWORD=admin123 pnpm --filter @fe-radar/db seed:admin`.
  - Playwright now injects local-only `AUTH_SECRET`, `AUTH_TRUST_HOST=true`, `NEXTAUTH_URL`, and `DATABASE_URL` defaults for its managed web server; production auth settings remain owned by deploy env.
  - The E2E login helper rejects Auth.js `CredentialsSignin` redirects instead of treating any 302 as success.

## Standard local E2E run (release smoke)

Prerequisites: migrated DB + seeded data + admin user.

```bash
# 1. Migrate & seed (one-time or after schema change)
pnpm --filter @fe-radar/db migrate
pnpm --filter @fe-radar/db seed:admin
pnpm --filter @fe-radar/db seed:release

# 2. Run release smoke (excludes @v11 which needs v11-smoke-prep.ts)
AUTH_TRUST_HOST=true \
  AUTH_SECRET="$(openssl rand -base64 32)" \
  NEXTAUTH_URL=http://localhost:3000 \
  DATABASE_URL=postgres://fe_radar:fe_radar@localhost:5432/fe_radar \
  E2E_ADMIN_USERNAME=admin \
  E2E_ADMIN_PASSWORD=admin-password \
  pnpm --filter @fe-radar/web e2e --grep "release smoke" --grep-invert "@v11"
```

Environment variables:

- `AUTH_TRUST_HOST=true` — required for local login without HTTPS.
- `AUTH_SECRET` — any base64 string; used for session encryption.
- `NEXTAUTH_URL` — must match the running web server origin.
- `DATABASE_URL` — PostgreSQL connection string.
- `E2E_ADMIN_USERNAME` / `E2E_ADMIN_PASSWORD` — must match `seed:admin` credentials (defaults: `admin` / `admin-password`).
- `REDIS_URL` — required if worker jobs are in the critical path (not needed for smoke-only).

## Release steps

1. Build images: `docker build -t registry.internal/fe-radar/web:v1.0.0 -f deploy/Dockerfile.web .` and worker equivalent.
2. Push images to the intranet registry.
3. Deploy with Portainer using `deploy/stack.yml`.
4. Run the smoke checklist above against the deployed internal URL.
5. Create and push `v1.0.0` only after Antigravity Gate 2 has 0 critical findings.
