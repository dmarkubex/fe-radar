## 2. 缺陷发现 (Findings)

### [Minor] M1: `template_version` 字段在 Schema 中缺失
- **位置**: `design.md §7.1` (Schema) / `design.md §9.4`
- **描述**: `design §9.4` 明确提到模板应有版本号，且简报应关联回版本号。但 `commodity_briefings` 表 Schema 中并未定义 `template_version` 列，仅在描述中提到存入 `payload_json`。
- **风险**: 纯 JSON 存储会导致未来难以通过 SQL 高效查询受特定模板改版影响的简报，且 `payload_json` 的结构可能会随模板版本变化，缺乏顶层字段约束。
- **修复建议**: 在 `commodity_briefings` 表中新增 `template_version INT NOT NULL` 字段。

### [Minor] M2: `briefing_targets` 缺少 `disabled_at` 软删机制
- **位置**: `design.md §7.1` / `tasks.md T-CB-18`
- **描述**: v1.0 的 `users` 和 `sources` 表都采用了 `disabled_at` (TIMESTAMPTZ) 配合 `enabled` (BOOLEAN) 的模式。v1.1 的 `briefing_targets` 仅有 `enabled` 字段，且 `T-CB-18` 提到"删除走软确认"，但未定义软删字段。
- **风险**: 与 v1.0 审计/清理模式不一致，物理删除会导致 `briefing_pushes` 的外键级联删除，丢失推送历史审计链。
- **修复建议**: 为 `briefing_targets` 增加 `disabled_at TIMESTAMPTZ` 字段，确保审计链完整。

### [Minor] M3: `commodity_quotes` 的 Upsert 冲突策略未定义优先级
- **位置**: `tasks.md T-CB-09`
- **描述**: 多个信源可能覆盖同一个 `metric_key` (如 SMM 和 交易所都报铜价)。`T-CB-09` 仅提到 "upsert by UNIQUE"。
- **风险**: 若两个 Source 抓取时间差或解析精度略有不同，会发生数据覆盖（Flickering）。
- **修复建议**: 在 `tasks.md T-CB-09` 中明确：Upsert 遵循 `T1 > T2 > T3` 的 Tier 优先级，或采用 `ON CONFLICT DO UPDATE SET value = EXCLUDED.value WHERE sources.tier <= current_tier` 逻辑。

## 3. 边界场景 (Edge Cases)

### [Edge] E1: `briefing-gen` 重试机制与 `quotes-fetch` 队列的竞态
- **描述**: 16:00 启动 `briefing-gen` 时，如果 15:30 的 `quotes-fetch` 队列因代理池故障导致严重积压，gen job 可能在数据未到位时就进入 retry 并最终 degraded。
- **修复建议**: 在 `T-CB-13` 的 precheck 逻辑中，增加对 `quotes-fetch` 队列状态的检查，若队列非空，应延长等待时间。

### [Edge] E2: `raw_text` 的长度截断单位歧义
- **描述**: `requirements §9.2` 提到 ≤2000 字符，`tasks T-CB-01` 提到 ≤2000 字节。
- **风险**: 对于包含大量中文的数据源，2000 字节可能只有 600 多字符，导致审计用的上下文信息不足。
- **修复建议**: 统一口径为 **2000 字符 (Characters)**，以确保审计信息的有效性。

### [Edge] E3: `computeSupportResistance` 样本不足的静默失败
- **描述**: 若因连续节假日或信源故障导致近 20 日样本 < 10，函数返回 null。
- **风险**: docx 模板中渲染为 "—" 可能会让用户困惑。
- **修复建议**: 在详情页 UI 或简报备注段，针对计算失效的情况，增加提示语："由于近期数据样本不足，支撑/压力位计算已降级"。

### [Edge] E4: `briefing_template_fields` Seed 数据的幂等性
- **描述**: `T-CB-03` 提到 `ON CONFLICT DO NOTHING`。
- **风险**: 如果 admin 手工在后台修改了默认映射，下次重跑 seed 会因为 Key 冲突而无法更新，但也不会报错。
- **修复建议**: 明确 Seed 仅用于首次初始化，或增加 `seed_version` 审计。
